## Deviations accepted (with reasons)

1. All N candidates are stored under `covers/`, winner included (plan: losers only) — a strip missing its chosen tile has to be reconstructed against `slide_01`; uniformity is the point of the strip.
2. `cover_pick.pick` is called even when ONE candidate landed (its pinned contract answers that case non-degraded); one call site, one vocabulary.
3. `chosen` is the SUBMISSION id, not a list index — a deck that lost candidate 2 keeps files `1` and `3`, and the gallery parses the id off the stem.
4. Runner COPY line is `N auto-compressed` / `N compressed (M auto)` rather than the brief's `N compressed (auto or compress)` — `_stage` gives that body 54 columns.
5. No extra covers are ordered when `env.llm_call is None` (`cover_candidates_unjudged`) — the plan said "any failure → candidate 1 + tag", which would have bought three renders to keep one; a run with the gauntlet off AND `cover_candidates > 1` now gets the seam wired by the runner anyway, so this path only fires in previews/tests.
6. `_COVER_PICK_PROMPT_TOKENS = 1600` is sized to the template's 6,000-char BOUND, not its 4,541 measured chars — D11's safe direction; revisit if the template is ever trimmed.
7. The registry kept `#FAFAF7` (declared) rather than `#F9F8F6` (the pixel L's drift script measured) — one step apart; a colour edit nobody asked for.
8. Wave 6 and Wave 7 ran in PARALLEL with the conductor pre-applying every shared-file edit (config, models, runner seam, prompts_engine branch, gallery row-reading, configs, the `cover_pick.py` interface skeleton) so no two agents touched one file — §9a trigger (c) answered by single-writer pre-work instead of an orchestrating parent.
