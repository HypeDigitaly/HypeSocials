TL;DR — Plain English

HypeSocials makes viral-style social posts from real trends. You double-click run.bat, pick a config, see the price, press Enter — and about 3 minutes later (up to ~8–10 if reels are in the mix) a folder holds finished images, carousels and short videos that copy the look and feel of posts that are actually going viral right now, plus captions and hashtags ready to paste.

  • Where trends come from: Virlo (via MCP) — including the real winning images, hooks and slide texts.
  • How mimicry works: an AI studies the winning visuals and writes a forensic style brief; the real winning images are also attached to every render so the output looks like the trend, not like generic AI art.
  • What it makes: images, multi-slide carousels (template-locked to slide 1), and 9:16 reels with built-in sound — hook text baked into a seed frame, then animated by a video model that can also study the actual winning video for movement and pacing.
  • What it costs: shown before anything is bought; the run refuses to start over your cap. Preview modes let you look at trends ($0) or briefs + copy (cents) first.
  • What it never does: no approval gates, no brand rules unless you switch Notion influence on, no publishing in MVP — you review the gallery and decide. Phase 2 pushes approved posts into Postiz as drafts.
  • Grows with you: order specific post types via small brief files (e.g. an AI-audit CTA that overrides the trend), and switch whole niches — restaurant UGC, AI agency, esoteric — by picking a different niche config file.
  • Everything is logged, nothing leaks: every call, prompt, dollar, and skip — while API keys never touch a prompt, a model, or a log line.

  1. Launch. Menu or CLI flags: config, source, formats × counts, budget, mode, Notion level. Cost estimate shown; nothing billable before the confirm.
  2. Collect. Virlo MCP returns trends with their winning videos and slideshows; reference images download concurrently. Optional local Inspiration folder and Notion context join in.
  3. Understand. Trends ranked by viral strength, recently-used ones skipped, then matched to creatives by format affinity (slideshow trends → carousels, video trends → images/reels). In analyzed mode, Sonnet 5 writes one forensic style brief per trend (JSON: layout zones, palette, exclusions, a compact render prompt).
  4. Create. One Luna copy call per trend covers all its creatives with distinct hooks that copy the structure of the viral originals. Render jobs submit concurrently in at most two dependency waves: carousels anchor to slide 1; reels animate a text-baked seed frame with the winning post's own video as a motion reference and native synchronized audio. Reference images ride along on every job via Kie's image-to-image route (input_urls, ≤16 — OQ-17 closed).
  5. Deliver. Optional single vision check (garbled text / fake platform UI, ≤1 retry). Everything packages into per-asset folders, an offline gallery with source references shown alongside, full logs, spend summary, trend history.
Preview modes: --preview-sources shows exactly what Virlo returned — $0. --preview-analysis adds the style briefs and drafted copy — LLM cost only, no renders. Both are true pipeline prefixes, not a separate code path.

§3Design Decisions D1–D35

Every locked decision from the grilling and review cycles, with its one-line why. Full rationale lives in the Markdown files.

D1

MCP for content, REST for inference

Virlo/Notion speak MCP; OpenRouter and Kie.ai stay plain REST. Postiz is the documented exception — its MCP can't upload media, so publishing runs over its web API.

D2

Dual mimicry modes, refs always attached

analyzed | direct | both. Real winning images ride on every render job — pixels beat prose; both channels together beat either.

D3

Zero gates, one optional vision check

Render once, ship. One narrow toggle-able check: garbled text / fake platform UI, ≤1 retry that shortens the text.

D4

No compliance layer

No disclosure lines, claim ledgers or lexicons. The operator reviews the gallery before anything is published.

D5

Python 3.13 async everywhere

asyncio + httpx + MCP SDK; Kie batch submission; wall clock = max of latencies, not sum.

D6

LinkedIn + Instagram + TikTok, EN + CS

Languages per platform; per-platform format allowlist — reels default to TikTok only.

D7

Notion influence knob

off | copy | full, default off. Live MCP fetch, cached per run. In full, the trend's visuals always win; brand supplies accent color + nouns.

D8

run.bat → interactive menu + flags

Menu pre-filled from config, Enter accepts; every choice also a CLI flag so Task Scheduler runs headless with --yes.

D9

Folders + offline gallery; Postiz drafts in Phase 2

Per-asset folders and one self-contained gallery.html; publishing is a later phase, drafts-only by default.

D10

Reels = one Seedance 2.5 clip

9:16, 720p, 4–30 s (verified range), single clip. No ffmpeg, no stitching — a video-editing suite is a different product.

D11

Estimate up front, cap at submission

Refuse to start over cap; enforce against the projected whole-batch total at submit time; tally on submission, failures included.

D12

Tiny state, total logging

One trend-history JSON + a complete per-run narrative log and structured events file. No database, no ledgers.

D13

Inspiration folder as a source

Local images join the reference pool as a weighted set; text files become copy exemplars. Off by default.

D14

Source adapters

One small adapter shape (normalized trend items). Google Trends and Hacker News are named future adapters, not built.

D15

Living PRD

Any amendment regenerates the Markdown, this HTML, the diagram — and republishes the artifact in the same cycle.

D16

TL;DR everywhere

Every PRD file opens with a plain-English summary readable in under a minute.

D17

Carousel anchor chaining, default on

Slide 1 renders first and becomes the primary reference for slides 2–N — the deck reads as one template.

D18

Reel text on a seed frame

Image models render text ~10× better than video models: bake the hook into a still, then animate around it.

D19

Preview modes, not --dry-run

--preview-sources ($0) and --preview-analysis (LLM cents) answer the two questions a dry run conflated.

D20

Source selection is first-class

sources.active in config + a menu picker; future adapters visible and honestly marked unimplemented.

D21

Python Virlo MCP wrapper

First-party MCP servers ship as Python in the same venv. An official Virlo MCP now exists (49 tools, headless Bearer) — the 5-tool wrapper stays by choice, official server is the swap path. Notion uses the token-based self-hosted server, with hosted-PAT mode as the sunset fallback.

D22

Reel audio in-model, default on

Seedance 2.5 generates synchronized AI audio natively (reel_audio: true) — viral video needs sound, and it costs one API boolean.

D23

Viral-video motion references

The winning post video (yt-dlp metadata probe before download, ≤28 s default — OQ-6 closed at the full ≤30 s tier — uploaded to Kie) becomes a Seedance reference for motion/pacing mimicry, fetched concurrently with Analyze. Any failure degrades to seed-frame-only, never blocks.

D24

Editable prompts/ folder

Every prompt scaffold is a plain-text template file with placeholders — tune prompt quality in Notepad, no code changes; missing file falls back to a built-in default.

D25

Researched prompt playbooks

GPT Image 2 and Seedance 2.5 prompting rules — from official docs, graded community research, and creator transcripts — are codified in 50-promptcraft.md and baked into the templates.

D26

Campaign briefs

Named brief files (e.g. ai-audit-cta) with copy + visual directives and an influence mode — override (replaces trend inputs) or blend (trend look stays, brief steers the message). Requested via --brief name:count.

D27

Niches are configs (v1.6.1)

A niche = an ordinary config file with a niche: descriptor (audience, vibe, visual world) plus three path keys pointing at its Inspiration, briefs, and prompt overrides. Switching niche = picking that config; no pack machinery, no --niche flag.

D28

Withdrawn (v1.6.1)

Declared media-richness + text-grounded mode removed — machinery for adapters that don't exist. A future text-only source marks items text_only and inherits the existing path.

D29

Postiz = committed Phase 2

Drafts + channel map + schedule slots, fully specified now (60-publishing-postiz.md) over Postiz's REST API; hosted cloud plan chosen (~$29/mo, skips Meta/TikTok app approvals); approval in the Postiz UI; auto-publish off by default.

D30

Absolute secrets hygiene

Keys live only in .env, never enter any prompt or template, never reach a model, and are redacted from all logs — they flow only into auth headers and MCP env dicts.

D31

Budget: three checkpoints + atomic reservation

Wave 1 (images, carousel anchors, reel seed frames) is checked as a whole-batch projection; wave 2 (slides 2–N, reel Seedance jobs) is pre-committed and always submits; every discretionary retry (vision, moderation, LLM) reserves its cost atomically before it fires. Trimming is deterministic — pair_id groups and carousels never split.

D32

Local references upload to Kie

Inspiration, brief and niche-pool images get public URLs via Kie's file-upload API before they can ride as references. A per-file upload failure degrades that one reference, never blocks the run.

D33

Native ratios everywhere; no local crop/pad (v1.6.1)

Every asset renders natively at its target aspect ratio (Kie's verified menu covers all defaults) and ships exactly as returned — the local crop/pad path is deleted. Chained references are always the Kie-hosted URL; reels stay 9:16 on every platform.

D34

Swappable models + provider seam

Every model id is a config string. A four-operation render-provider interface (submit → poll → results → upload) with Kie as the only built implementation; two model profiles ship (GPT Image 2, Seedance 2.5). Same-profile swap = one config edit; a new family = profile + template set per a one-page recipe. Higgsfield evaluated 2026-08-09 and parked: no Seedance 2.5 (waitlist), account-auth MCP, subscription pricing (OQ-18).

D35

Product ads now, long video parked

Product-photo-to-ad ships as a worked campaign-brief example — your product photos as brief references + high-retention ad directives, zero new machinery. Extension chaining (>30s videos) and audio-reference music videos wait behind the provider seam until an API actually exposes them.

§4Pipeline Highlights (full spec: 10-pipeline.md)

Format affinity. Slideshow-backed trends go to carousels (the source already is a carousel — panel counts, panel texts and narrative arc transfer 1:1); video-backed trends go to images and reels. Text-only trends are last resort.
Structural copy mimicry. Luna must restate the source hook's abstract pattern ("[number] + [thing you do] + [consequence]") and instantiate it — matching syntax, cadence, word count — with 3–5 verbatim viral hooks as few-shot examples and an auditable hook_pattern_used field. If the grouped per-trend call fails it splits into per-creative calls; total failure falls back to the trend's own hook text and a minimal caption, marked copy_degraded.
Coherent references, cleaned prompts. 2–3 references from one slideshow or one creator (never a top-engagement mix); every prompt carries a mandatory exclusion clause — never reproduce platform UI, watermarks, usernames or the reference's own text.
Moderation fallback. Policy refusals (face-heavy references) are their own failure class: one resubmission without references, marked refs_dropped_moderation. A creative degrades; it doesn't die.
Budget that actually bites. Enforced at three points, not one: wave 1 (images, carousel anchors, reel seed frames) is checked as a whole-batch projection; wave 2 (slides 2–N, reel Seedance jobs) is pre-committed and always submits; every discretionary retry reserves its cost atomically before it fires. Reels can't even be planned until their unit price is configured.
Degrade and report, never block. Failure is scoped to one creative or slide; partial carousels ship labeled; failed creatives keep their paid copy; a global run deadline (~25 min) guarantees the run always ends and packages. Ctrl+C triggers a graceful abandon-and-package (an outstanding-task ledger tracks every submitted job); exit codes 0–4 distinguish full / partial / pre-flight-refusal / fatal / interrupted.

§6bPromptcraft (full spec: 50-promptcraft.md)

Who writes the generation prompts: three layers — the Sonnet 5 style brief supplies the creative substance, editable templates in prompts/ supply model-specific scaffolding, and deterministic assembly fills the placeholders. No extra LLM call; the templates are the encoded expertise, tunable in Notepad, hot-loaded per run, name+hash logged.

GPT Image 2 playbook (official docs + graded research): fixed section order (use-case → scene → exact text → style → constraints), text as a locked asset — quoted strings, stated typography, letter-by-letter spell-out for Czech diacritics, "render verbatim, no extra characters"; quality tier medium/high whenever text is present; style-DNA scaffold repeated verbatim across carousel slides with only content fields changing; stateless anchor-referenced calls (avoids the documented "same-chat ghosting"); no vague quality tags; ≤2K production ceiling.
Seedance 2.5 playbook: director format — GOAL → REFERENCES → CONTINUITY → SCENE → STAGES → LOOK → CAMERA → AUDIO → RULES — over the official six-part formula; one sentence per @tag stating what it contributes and what it must not; hook text protected via CONTINUITY/RULES, never the generative 【 】 subtitle bracket; audio brackets ( ) music · < > SFX; @Video1 scoped to motion/pacing only (its people, captions, and music explicitly excluded); 2–4 timed stages with one primary change each; UGC realism vocabulary ("handheld, phone-camera look, slight grain, no 3D, no VFX").

§6cPublishing — Phase 2 (full spec: 60-publishing-postiz.md)

After gallery review, --publish <run_id> pushes chosen creatives into Postiz as drafts: media uploaded per file, one post entry per platform with its own caption and settings (Instagram carousels/reels, TikTok's required fields with video_made_with_ai: true, LinkedIn document carousels), channel map resolved from your connected Postiz accounts. You approve inside Postiz; --promote or schedule slots (e.g. next free 09:00/18:00) take it from there. Auto-publish exists as a config flag and defaults off. Publishing is idempotent: assets carrying PUBLISHED.marker are always skipped (delete the marker to deliberately re-publish — v1.6.1 removed --force and the automated reconciliation; a lingering attempt-marker is named in the summary for a quick manual glance). Uploaded media ids are cached in each asset's meta.yaml, so a retry reuses them instead of re-uploading. Research verdict encoded honestly: Postiz's MCP server cannot ingest external media, so publishing runs over its public REST API. Deployment choice: hosted Postiz cloud (~$29/mo Standard) — skips Docker ops and the weeks-long Meta/TikTok developer-app approvals; self-hosting stays a config-only fallback.

Also in this design: campaign briefs (specific post types that override or blend with trends), niche configs (switch business/vertical by picking a config), and absolute secrets hygiene (keys never in prompts, models, or logs).
